# Accessibility Audit

Last updated: 2026-08-21

## Summary

DeLaClaw has basic accessibility support but several gaps that should be addressed. This document catalogs findings organized by severity and provides recommendations.

## What works

- **Keyboard shortcuts**: Alt+Left/Right to navigate between tabs
- **Escape key**: closes all modals consistently
- **Form labels**: login form has proper `<label for="...">` associations
- **Search clear buttons**: have `aria-label="Clear search"`
- **Focus management**: modals auto-focus their first input on open
- **Semantic HTML**: uses `<header>`, `<button>`, `<form>`, `<label>`, `<input>`, `<select>` appropriately
- **Tab navigation buttons**: use `<button>` elements (not clickable `<div>`s)
- **Color themes**: both dark and light themes work, respecting `prefers-color-scheme`

## Critical issues

### 1. No ARIA roles on modals

Modals use `<div class="modal-overlay">` without `role="dialog"` or `aria-modal="true"`. Screen readers cannot distinguish modals from regular page content.

**Recommendation**: Add `role="dialog"` and `aria-modal="true"` to modal overlays. Add `aria-labelledby` pointing to the modal's heading.

### 2. No focus trapping in modals

When a modal is open, Tab can move focus to elements behind the modal overlay. Users can interact with the main page while a modal appears to be active.

**Recommendation**: Implement focus trapping. On modal open, restrict Tab/Shift+Tab to elements within the modal. On close, return focus to the element that triggered the modal.

### 3. Icon-only buttons without accessible names

Many action buttons contain only an SVG icon (via `lucideIcon()`) without a text label or `aria-label`. Examples:
- "Add task" buttons in project cards: `<button onclick="addTask('...')">${lucideIcon('plus', 16)}</button>`
- "Add todo" buttons in category cards
- "Add habit" quick-add buttons
- Various edit/delete action buttons in hover menus

Some buttons have `title` attributes (which provides a tooltip but is not reliably read by all screen readers).

**Recommendation**: Add `aria-label` to all icon-only buttons. The `title` attribute can remain for mouse users.

### 4. Missing alt attributes on images

Two `<img>` elements in the birthday avatar cropping UI lack `alt` attributes (search for `avatar-crop-img` in `js/birthdays.js`).

**Recommendation**: Add `alt="Avatar preview"` or similar.

## Important issues

### 5. Color contrast -- muted text

The `--muted` color is `#6c6f7e` on dark (`#08090d` background) and `#71717a` on light (`#edeeed` background).

- Dark theme: `#6c6f7e` on `#08090d` = contrast ratio ~4.0:1. Meets AA for large text but fails AA for normal text (requires 4.5:1).
- Light theme: `#71717a` on `#edeeed` = contrast ratio ~4.2:1. Also fails AA for normal text.

`--muted` is used extensively for secondary labels, timestamps, and metadata.

**Recommendation**: Increase lightness of `--muted` in dark theme (e.g. `#8b8d9a`) and decrease in light theme (e.g. `#5c5c66`) to meet 4.5:1 minimum.

### 6. Drag-and-drop not keyboard accessible

Drag-and-drop reordering uses mouse-only HTML drag events. There is no keyboard alternative for reordering items.

**Recommendation**: Add keyboard reordering (e.g. Alt+Up/Down when focused on an item). This is a larger feature and can be tracked separately.

### 7. No skip-to-content link

There is no mechanism to skip the header and tab navigation when using Tab to navigate.

**Recommendation**: Add a visually hidden "Skip to main content" link as the first focusable element in the page.

### 8. Dynamic content not announced

When data loads or updates (e.g. after adding a task, completing a habit), there is no ARIA live region to announce the change to screen readers.

**Recommendation**: Add an `aria-live="polite"` region for toast notifications and status updates. The existing `showToast()` function could update this region.

## Minor issues

### 9. SVG icons lack aria-hidden

All Lucide icons are decorative (adjacent to text labels or inside labeled buttons) but are not marked with `aria-hidden="true"`. Screen readers may attempt to read SVG content.

**Recommendation**: Add `aria-hidden="true"` to the SVG elements generated by `lucideIcon()`.

### 10. No lang attribute on translated content

When the UI language is changed (FR, ES), the `<html lang="...">` attribute is not updated. Screen readers may use the wrong pronunciation rules.

**Recommendation**: Update `document.documentElement.lang` when the language setting changes.

### 11. Touch targets on mobile

Some action buttons (edit, delete, priority icons) are small on mobile. WCAG recommends a minimum touch target of 44x44px.

**Recommendation**: Review and increase padding on small interactive elements for mobile viewports.

## Fixes applied in this commit

The following critical fixes were applied directly:

1. **`lucideIcon()` -- added `aria-hidden="true"`** to all generated SVG icons, since they are decorative
2. **Missing alt attributes** on birthday avatar crop images
3. **`<html lang>` attribute** updated when language changes
