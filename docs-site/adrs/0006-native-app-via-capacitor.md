# ADR-0006 — Native App Distribution via Capacitor

**Status:** Proposed  
**Date:** 2026-08-15  
**Deciders:** Antoine Grosnit  

## Context

DeLaClaw is a static single-page app (vanilla JS, ES modules, no build step) served from GitHub Pages and Cloudflare Pages. It already ships as a PWA with a service worker, offline cache, and a web manifest.

PWA installation works well on Android and reasonably on iOS, but native app distribution through the App Store and Play Store would unlock:

- **Push notifications** — reliable, OS-integrated, no browser permission friction.
- **Deeper offline support** — native file system access, background sync.
- **Discoverability** — app store presence, search indexing.
- **OS integration** — biometrics (Face ID / fingerprint for app lock), share sheet, home screen widgets.

The question is which wrapper technology best fits DeLaClaw's architecture: no framework, no build step, ~17k LOC vanilla JS with ES module imports.

## Decision

Use **Capacitor** (by Ionic) to wrap the existing web app in a native shell for iOS and Android.

### Why Capacitor

- **No rewrite required.** Capacitor loads the existing web assets through a local web server inside the app. ES module imports (`type="module"`) work out of the box. The current codebase stays as-is.
- **No build step required.** Capacitor's `webDir` points at the repo root (`.`). `npx cap sync` copies files into the native projects. No bundler, no transpiler.
- **Incremental native access.** Native features (notifications, biometrics, file system) are added one plugin at a time. Each is an npm package with a JS API and native implementation. No all-or-nothing commitment.
- **OTA web updates.** The `capacitor-updater` plugin enables over-the-air updates for the web layer without going through store review. This preserves the current deploy-on-merge workflow for the vast majority of changes.
- **Mature ecosystem.** Capacitor is the successor to Cordova, backed by Ionic, with broad plugin coverage and active maintenance.

### Alternatives considered

| Option | Verdict |
|---|---|
| **TWA (Trusted Web Activity)** | Android-only. Minimal effort but no iOS support, no native API access. Too limited. |
| **Tauri 2.0** | Lighter binaries, Rust-based. Mobile support is newer, plugin ecosystem thinner. Higher setup complexity for marginal gains on a ~17k LOC app. |
| **React Native / Flutter** | Full rewrite. Contradicts ADR-0001 (no framework, no build step). Not viable. |
| **PWA only** | Current state. Works, but no push notifications on iOS, no App Store presence, limited OS integration. |

## Implementation outline

### Repo structure (additions only)

```
capacitor.config.ts     # Points at webDir: '.'
package.json            # Capacitor deps only, no bundler
ios/                    # Generated by `npx cap add ios`
android/                # Generated by `npx cap add android`
```

### Initial setup

```bash
npm init -y
npm install @capacitor/core @capacitor/cli
npx cap init "DeLaClaw" "com.delaclaw.app" --web-dir .
npx cap add ios
npx cap add android
npx cap sync
```

### Day-to-day workflow

1. Develop on `dev` as usual — no change to the web workflow.
2. `npx cap sync` before native testing (copies web assets into platform projects).
3. Web-only changes: push OTA via `capacitor-updater`, no store submission.
4. Native changes (new plugin, permission change): build + submit via Fastlane.

### CI/CD (later phase)

GitHub Actions with macOS runners can handle iOS + Android builds and Fastlane submission. This decouples store releases from the developer's local machine.

### Service worker consideration

The existing service worker (`sw.js`) manages its own cache (`CACHE_VERSION` + `PRECACHE_URLS`). Inside Capacitor, web assets are served from the local file system, not a remote origin. The service worker should either:

- Be disabled inside the native app (Capacitor config: `server.iosScheme` / `server.androidScheme` can make the SW no-op), or
- Be kept but with awareness that `capacitor-updater` handles asset freshness, not the SW cache.

This is a small, one-time configuration choice — not a structural change.

### Store requirements

| | Apple App Store | Google Play Store |
|---|---|---|
| **Developer account** | $99/year | $25 one-time |
| **Build tool** | Xcode (macOS only) | Android Studio (any OS) |
| **Review time** | 1–3 days | < 1 day typically |
| **Key requirement** | Must feel "native enough" — push notifications + offline recommended before submission | More permissive, TWA-level apps accepted |

### App identity

- **Bundle ID:** `com.delaclaw.app` (or `com.practiae.delaclaw` if using the practiae.com domain)
- **Display name:** DeLaClaw
- **Icons:** Existing 192px and 512px icons. App stores need additional sizes (1024px for Apple) — generate from the same source.

## Consequences

- **package.json enters the repo** — but only for Capacitor dependencies, not for a build pipeline. ADR-0001's no-build-step principle is preserved: there is no transpile, no bundle, no compile for the web layer.
- **ios/ and android/ directories are generated and committed** — they contain native project files (Xcode project, Gradle build). These are mostly stable; changes happen when adding plugins or updating Capacitor versions.
- **Two deployment channels** — web (Cloudflare Pages / GitHub Pages, instant) and native (store submission, 1–3 day review). OTA updates blur this line for web-only changes.
- **macOS required for iOS builds** — either locally or via CI runners.
- **No lock-in** — the web app continues to work standalone. Capacitor is additive. Removing it means deleting `ios/`, `android/`, `capacitor.config.ts`, and the Capacitor npm packages. The web app is unaffected.
